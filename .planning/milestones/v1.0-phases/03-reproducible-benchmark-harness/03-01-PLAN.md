<threat_model>
Benchmark credibility risks:
- Raw results without environment metadata can be copied into claims that cannot be reproduced.
- Unlabeled CUDA event timing can be misread as end-to-end application throughput.
- CUDA event leaks can accumulate during long benchmark runs or future expanded mode matrices.
- Adding CLI features can accidentally change default benchmark behavior.

Mitigations:
- Add explicit metadata fields for environment, parameters, command, and timing scope.
- Label existing CUDA event timing as `kernel_only`.
- Destroy CUDA events on all successful timed paths or use a small RAII wrapper.
- Keep default mode/size/run behavior compatible unless new flags are explicitly supplied.
</threat_model>
