<threat_model>
T-REL-01: Release notes can imply final verification when CMake/CTest/benchmark execution is still blocked.
Mitigation: Mark output as release candidate until the runtime gate passes; record blockers plainly in `08-VERIFICATION.md`.

T-REL-02: Release assets can include stale or unverified throughput files.
Mitigation: Attach or list only artifacts produced by the current verified release-gate run.

T-REL-03: `CHANGELOG.md` can be promoted prematurely.
Mitigation: Promote `Unreleased` into a dated `v1.0.0` section only after the release gate passes; otherwise leave final promotion pending.

T-REL-04: v1 wording can imply production cryptography API stability.
Mitigation: Say v1 stabilizes the benchmark/reproducibility contract, not a production cryptography library API.

T-REL-05: Release notes can introduce ranking or fastest-in-world claims.
Mitigation: Keep claims environment-specific and tied to raw artifacts and `timing_scope`.
</threat_model>
