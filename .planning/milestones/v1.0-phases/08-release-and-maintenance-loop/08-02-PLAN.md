<threat_model>
T-SEC-01: Public security guidance can accidentally ask reporters to disclose sensitive details in issues.
Mitigation: Prefer GitHub private vulnerability reporting when enabled and explicitly tell reporters not to include sensitive data in public issues.

T-SEC-02: Security policy can imply production cryptography support.
Mitigation: Preserve benchmark/research software scope and say production library/API guarantees are out of scope for v1.

T-MAINT-01: Maintenance process can become too vague to keep the repo alive after v1.
Mitigation: Document concrete triage categories, changelog rules, roadmap update triggers, and benchmark-result review expectations.

T-MAINT-02: Future v2 ideas can leak into v1 maintenance scope.
Mitigation: Keep GMAC/CMAC benchmarking, charts, matrix automation, GitHub Pages, DOI releases, paper-style reports, and library/API work in a future-work section.
</threat_model>
