<threat_model>
GCM security risks:
- Accepting plaintext without authenticating tag defeats AEAD integrity.
- Non-standard tag generation can make local benchmark output incompatible with NIST/OpenSSL.
- Warp-local IV broadcast can corrupt counter state for most threads in a 256-thread block.
- A plaintext buffer may contain unauthenticated data after a failed tag check.

Mitigations:
- Compute standard GCM tag using `J0`, GHASH with length block, and final `E(K, J0)` XOR.
- Replace warp-local IV sharing with block-wide shared-memory state.
- Add negative tag/ciphertext tests that fail if plaintext-only round-trip is accepted.
- Make host round-trip PASS depend on tag verification for GCM.
</threat_model>
