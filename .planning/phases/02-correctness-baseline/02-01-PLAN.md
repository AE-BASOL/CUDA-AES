<threat_model>
Correctness harness risks:
- False positives can bless broken cryptography.
- Random round-trip tests can miss standard-vector mismatches and can repeat symmetric bugs.
- A large benchmark-sized test can be skipped by developers because it is slow.

Mitigations:
- Use fixed NIST/OpenSSL-compatible vectors.
- Include byte-for-byte expected ciphertext/tag comparisons.
- Keep all correctness buffers small and deterministic.
- Register tests through CTest or an equally obvious command.
</threat_model>
