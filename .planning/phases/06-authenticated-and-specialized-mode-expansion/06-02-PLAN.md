<threat_model>
T-XTS-01: XTS can use the wrong key schedule for tweak encryption or data encryption because current device constant memory stores one active schedule.
Mitigation: Make two-key handling explicit in implementation and tests; use host orchestration if needed for correctness.

T-XTS-02: XTS can be mislabeled as AEAD or generic bulk encryption.
Mitigation: Docs must describe storage-sector confidentiality scope and lack of authentication.

T-XTS-03: Ciphertext stealing can be assumed by readers if only full-block sectors are implemented.
Mitigation: State full-block scope or implement/test ciphertext stealing explicitly.
</threat_model>
